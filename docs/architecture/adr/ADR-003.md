# ADR-003. Выбор объектного хранилища

## Статус
Принято

## Контекст
Проект «Business Metrics Analyzer» — веб-приложение для расчёта и визуализации KPI торговой компании. Разработка ведётся командой из четырёх человек, требуется быстрый MVP с возможностью последующего масштабирования. Приложению необходимо хранить неструктурированные файлы: сгенерированные отчёты, экспортированные датасеты, графики и, возможно, резервные копии. Реляционная СУБД (PostgreSQL) для этой цели не предназначена, поэтому требуется отдельное объектное хранилище, совместимое с S3 API.

## Решение
Принято решение использовать MinIO в качестве S3-совместимого объектного хранилища, развёртываемого на собственном сервере. MinIO представляет собой лёгкий бинарный файл без внешних зависимостей, полностью совместим с Amazon S3 API, что позволяет использовать стандартные SDK и инструменты без привязки к конкретному облачному провайдеру

## Альтернативы
1. **S3 (Amazon / облачный провайдер)** — управляемый сервис, не требует администрирования. Однако для проекта, разрабатываемого в России, AWS фактически недоступен: регистрация новых аккаунтов из РФ приостановлена, российские карты не принимаются, а использование возможно только через иностранные платёжные посредники, что создаёт неприемлемый риск потери доступа для учебного MVP. 
2. **RustFS** — молодой S3-совместимый проект с лицензией Apache 2.0, позиционируемый как более лицензионно-дружелюбная альтернатива MinIO. На момент принятия решения не имеет достаточной зрелости и стабильности для учебного проекта.

## Последствия
+ Отсутствие зависимости от зарубежных облачных провайдеров: MinIO развёртывается локально и не требует оплаты или регистрации в сервисах, недоступных из России.
+ Код приложения не зависит от конкретного провайдера, при необходимости можно перейти на облачный S3 или другую совместимую реализацию без изменения логики.
+ Развёртывание на собственном сервере не требует оплаты облачных тарифов за хранение и запросы.

- MinIO Community Edition переведён в режим поддержки: новые функции и исправления безопасности для бесплатной версии не гарантированы, что создаёт долгосрочный риск для проекта
- Требуется самостоятельное администрирование: резервное копирование, обновления и мониторинг хранилища ложатся на команду
- Лицензия AGPL v3 накладывает ограничения при сетевом использовании модифицированной версии
